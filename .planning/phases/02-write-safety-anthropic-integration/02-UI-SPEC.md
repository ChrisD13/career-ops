## Typography

Inherits Phase 1 scale. **Exactly four roles, two weights (400 and 600). No new roles added, and no size exceptions below the declared scale.**

| Role | Size | Weight | Line Height | Phase 2 additional usage |
|------|------|--------|-------------|--------------------------|
| Body | 13px | 400 | 1.5 | Streaming report body (via react-markdown pipeline), CV body, Settings inputs, inline error text, drawer tab labels, operations log drawer monospace text |
| Label | 11px | 600 | 1.4 | Token stats row labels ("Input", "Cache hit", "Cost", "Model"), Settings field labels, drawer tab badges, operation timestamps |
| Heading | 16px | 600 | 1.3 | Evaluate panel title, CV panel title, Settings slide-over title, drawer tab active label |
| Display | 20px | 600 | 1.2 | Unchanged — only used for markdown H1 inside streaming report and inside CV viewer |

**Font stack (unchanged):** `'Inter', ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, sans-serif`

**Monospace usage (Phase 2 additions):**
- Operations log drawer text: `ui-monospace, SFMono-Regular, Menlo, Monaco, monospace`, **13px** (Body size), line-height 1.45. **Note:** Monospace fonts render visually smaller and denser than Inter at the same point size — the log drawer achieves VS-Code-style line density without introducing a 5th font size. Timestamps are 11px Label tone in `ctp-subtext`; line numbers are hidden.
- Evaluate URL input: `font-mono` 13px (URLs benefit from monospace alignment, matches the Phase 1 Pipeline panel URL rendering pattern).
- Token stats row numeric values: `font-mono` 13px for alignment when values update (Input/Cache numbers). Labels remain Inter 11px.
- Streaming report code blocks: reuse Phase 1 `ReportViewer` code block styling verbatim.

**Report markdown rendering (streaming):** Reuses the exact component map from `ReportViewer.tsx` — no new typography mappings. Live-rendering while streaming requires that tokens accumulate into a string and re-render through the existing `<Markdown>` component each frame; the visual output is identical to the final rendered report.

**Sidebar footer — new layout (D-07, D-18):**

Above the existing collapse toggle (which stays at the absolute bottom), insert a 40px-tall strip containing:

- Left half: gear icon button (lucide `Settings`, size 16, color `ctp-subtext` → `ctp-text` on hover). Aria-label: `"Settings"`. Click opens the Settings slide-over.
- Right half: operations status indicator. Three possible states:

When sidebar is collapsed (48px width), the footer strip stacks vertically: gear icon on top, operations indicator below, each in a 32px square. The expand/collapse toggle remains at the very bottom (unchanged from Phase 1).

### StatusSelect per-row activation (D-12, D-13, D-14, D-15)

Upgrades the Phase 1 stub. The single above-list disabled `StatusSelect` is **removed**. Each tracker row's Status column cell becomes interactive.

**Idle-row appearance (unchanged visually from Phase 1):** `StatusBadge` pill renders exactly as before. Cursor on the status cell hover: `pointer`. Subtle visual hint: on row hover (which already changes row bg to `ctp-overlay`), the status cell gets a thin 1px outline in `ctp-overlay` to signal "this is editable". No other visual change.

**Click-to-activate (per-row only):**
- Clicking the status cell replaces **only that row's** badge with a `<select>` element
- Select dimensions: 28px height (fits within 32px row), 120px width (matches the Status column), font-size 13px Body
- Background `ctp-base`, border 1px `ctp-blue`, focus ring `ctp-blue` 2px
- Options loaded from `templates/states.yml` (same data source as Phase 1 StatusSelect)
- Default selection: the row's current status
- Keyboard: receives focus on activation; Escape cancels back to badge; Enter applies selection; Tab moves to next row's status cell (the only cell it can tab to — other cells are read-only)

**Auto-save behavior (D-13):**
- Change event (user picks a new value) immediately triggers `updateStatus` IPC call
- Optimistic UI: row renders new status badge instantly
- If IPC resolves successfully: dropdown collapses back to badge; no additional visual signal
- If IPC rejects (lock timeout, parse error): inline error strip slides down below the row (44px height, spans full width of tracker, red border-left, same dismissible pattern as Evaluate error banner); row reverts to previous status; dropdown stays open so user can retry

**Only one row editable at a time:** Clicking a second row's status cell commits any pending edit in the first row (fires the change event if dirty) and activates the dropdown on the new row.

**Outside click / blur:** Commits (same as picking a value). No implicit cancel — the change event already fired the save.

**`pendingGuiWrite` flag behavior (D-15):** The user-initiated status write sets a flag in the main process that suppresses the `FileChangeBanner` for 500ms after the save completes (debounce matches chokidar's default). User sees: badge change instantly, no jarring banner.

### Operations log drawer (D-18)

VS Code-style bottom drawer. Collapsible, resizable, tabbed.

**Collapsed state (handle visible):** 24px tall strip anchored to the bottom of the viewport, spanning the full width (below sidebar and main content).
- Background `ctp-surface`, top border `ctp-overlay` 1px
- Left content: `"Logs"` label (Label 11px/600 `ctp-subtext`) + optional badge for the most-recent operation state:
  - Running: `Loader2` spinner + count (e.g. `"Logs · 1 running"`)
  - Error: red dot + label (e.g. `"Logs · 1 failed"`)
  - Idle: just `"Logs"`
- Right content: lucide `ChevronUp` size 14 `ctp-subtext` (toggles to expand)
- Click anywhere on the strip to expand

**Expanded state:** 240px default height (user-resizable 120-480px via 2px top-edge drag handle, cursor `row-resize`), full width.
- Top row (36px): tab bar
  - Tabs per active process, each tab: Label 11px text, 12px horizontal padding, 36px height
  - Inactive tab: `ctp-subtext` text, no bottom border
  - Active tab: `ctp-text` text, 2px bottom border in `ctp-blue`
  - Tab with non-zero exit: red 6px dot before the label, `ctp-red`
  - Tab running: `Loader2` spinner before the label, `ctp-yellow`
  - Max simultaneous tabs: 4 (Scan, Batch, PDF, Evaluate). If a 5th process starts, the oldest inactive tab is closed.
  - Right-aligned close button: lucide `ChevronDown` size 14 — collapses drawer
- Body (fills remaining drawer height):
  - **Monospace 13px `ctp-text` text, line-height 1.45** (same Body size as the typography contract; monospace glyph width keeps it visually dense without going below the declared scale)
  - Each line: timestamp `[HH:MM:SS]` in Label 11px `ctp-subtext`, 8px gap, then line content in `ctp-text`
  - stderr lines rendered in `ctp-red`
  - Auto-scroll to bottom unless user manually scrolls up
  - Scrollbar styled to match Tailwind default dark
  - Horizontal scroll on overflow (no wrap) — logs often contain paths and JSON that break on wrap

**Auto-behaviors (D-18):**
- Drawer auto-opens when any operation starts
- On clean exit (code 0), drawer auto-collapses after 5 seconds
- On non-zero exit, drawer stays open; the errored tab shows red dot; drawer does not auto-collapse until user manually collapses or the errored tab is closed
- If user manually collapses mid-run, do not auto-reopen on same-process output (respect user intent). Auto-reopen only on *new* process start.

## Accessibility Contract

Extends Phase 1 accessibility rules. All rules from `01-UI-SPEC.md` apply; Phase 2 additions below.

- **Focus order on the Evaluate panel:** URL input → Evaluate button → (if in-flight) Stop Evaluation button → streaming output region (as `role="region"` with `aria-label="Evaluation report"`; scrollable focus target)
- **Streaming output live region:** The streaming output container has `aria-live="polite"` and `aria-busy="true"` while streaming. On completion, `aria-busy="false"`. Screen readers announce periodic progress without interrupting.
- **Settings slide-over focus trap:** On open, focus moves to the API key input. Tab cycles within the panel. Escape dismisses.
- **Settings slide-over close button:** `aria-label="Close Settings"` on the lucide `X` button in the header.
- **First-run banner dismiss button:** `aria-label="Dismiss banner"` on the lucide `X` button at the right end of the banner.
- **API key reveal toggle:** Button has `aria-pressed={revealed}` and `aria-label="Show API key"` / `"Hide API key"`.
- **Model `<select>`:** Native HTML select — inherits full platform a11y. No custom ARIA needed.
- **StatusSelect per-row dropdown:** When activated, the `<select>` receives `aria-label="Edit status for application {num} — {company}, {role}"` so screen readers identify which row is being edited.
- **Operations drawer:** The drawer handle button has `aria-expanded` reflecting collapsed/expanded state and `aria-controls="operations-log"`. The drawer body has `role="log"` and `aria-live="polite"` so log output is announced incrementally.
- **Tab bar in drawer:** `role="tablist"`; each tab `role="tab"` with `aria-selected`; each tab panel `role="tabpanel"` with `aria-labelledby`.
- **PDF toast:** `role="status"` with `aria-live="polite"`. Auto-dismiss does not strand keyboard focus.
- **Inline error banners (Evaluate, StatusSelect):** `role="alert"` so screen readers announce immediately.
- **Color is never the sole differentiator:** cache-hit state includes the percentage number AND text ("warming (first run)" vs "X%"); drawer error tab includes the red dot AND a word in the tab label; token stats row values are numeric text, not just colored.
- **Contrast:** All text on its backgrounds clears WCAG AA at 4.5:1. Spot-checked: `ctp-text` on `ctp-surface` = ~11.4:1; `ctp-red` on `ctp-red/15` over `ctp-base` = ~4.9:1; `ctp-green` text on `ctp-surface` = ~8.7:1.
- **Keyboard-only operability:** Every Phase 2 interaction in the table above is reachable via keyboard. No hover-only affordances.
