# Phase 3 — UI Design Contract: VC Portfolio Discovery

> Visual and interaction contract for Phase 3 frontend implementation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Phase 3 **extends** the Phase 1 and Phase 2 design systems — it introduces no new tokens, fonts, or palette entries. Every decision below inherits from `01-UI-SPEC.md` and `02-UI-SPEC.md` unless explicitly overridden. Where this document is silent, prior phases apply.

### Discover panel (D-05, D-06, D-07, D-10, D-11, D-13)

New primary panel. Dedicated full-viewport view for VC portfolio browsing.

**Layout (top to bottom):**

1. **Drop alert banner** (D-11, conditional — only rendered when `vc-health.json` reports any firm with count drop > 20% from baseline):
   - 40px height, full-width of panel
   - Background `ctp-yellow/15` (warn tier, 20–40% drop) or `ctp-red/15` (critical tier, > 40% drop), border-bottom 1px in matching accent
   - Icon left: lucide `AlertTriangle` size 14 (yellow or red matching tier)
   - Copy: see Copywriting Contract
   - Right: `"View firms"` inline link (blue text, underline on hover) scrolls the panel to expand the health accordion and highlights the affected firm rows with a 2px blue outline for 2 seconds
   - Right end: `X` dismiss button — lucide `X` size 14, `ctp-subtext` hover `ctp-text`, `aria-label="Dismiss banner"`. Dismissed for the session only; reappears next time the panel is opened if the drop condition still holds.
   - Matches Phase 1 `FileChangeBanner` visual pattern exactly (same tint treatment, same dismiss mechanic).

2. **Panel header strip** (44px height, sticky top, bg `ctp-surface`, bottom border `ctp-overlay`):
   - 24px horizontal padding, flex row, 16px gap between groups
   - Left: `"Discover"` heading (Heading 16px/600 `ctp-text`)
   - Center-left: `"Showing: Matched (N) / Show all (M)"` filter toggle (D-07) — described as the Filter Toggle block below

3. **Filter toggle** (D-07) — a two-state segmented pill occupying the center of the header:
   - Two buttons joined edge-to-edge: `"Matched (N)"` and `"All (M)"`, each 28px tall, 12px horizontal padding
   - Active side: bg `ctp-overlay`, text `ctp-text`, font-weight 600
   - Inactive side: bg transparent, text `ctp-subtext`, border 1px `ctp-overlay`
   - Default state: `"Matched"` active (D-07 explicit — signal-forward)
   - Counts update live as data loads; counts in Label 11px `ctp-subtext` inside the button text
   - Switching sides re-renders the table; no in-place animation (avoids jitter on large datasets)

4. **Scraper health accordion** (D-10) — collapsed by default:
   - 32px collapsed handle row (bg `ctp-surface`, border-bottom `ctp-overlay`), 24px horizontal padding, flex row
   - Left: Label 11px `ctp-subtext` `"Scraper health"` + an inline summary pill showing `"10/10 OK"` or `"8/10 OK · 2 Stale"` (Label text, not badge-colored — keep accent color discipline)
   - Right: lucide `ChevronDown` size 14 `ctp-subtext` (flips to `ChevronUp` when expanded)
   - Click anywhere on the handle row expands; click again collapses
   - **Expanded state:** 200px default height, internal scroll if more than 10 firms:
     - Content is a 4-column table with 36px sticky header and 28px rows (tighter than the main company table because this is informational, not actionable)

     - Firm column: Body 13px `ctp-text`, left-aligned, 160px width

     - Count column: `font-mono` 13px `ctp-text` right-aligned with tabular-nums, 80px width; when `count < baseline_count * 0.8`, cell text turns `ctp-yellow`; when `count < baseline_count * 0.6`, cell text turns `ctp-red`

       - `OK` — green dot + `"OK"` Label 11px `ctp-green`
       - `Stale` — yellow dot + `"Stale"` Label 11px `ctp-yellow` (last_run outside configured interval)
       - `Error` — red dot + `"Error"` Label 11px `ctp-red` (last run ended non-zero)

5. **Company table** (D-06) — the primary content area, fills remaining viewport height under banner + header + health accordion:
   - react-window `FixedSizeList` with 36px row height (reuses the Phase 1 virtualization pattern; DiscoverPanel treats the list the same way TrackerPanel does)
   - Sticky header (36px, Label typography, bg `ctp-surface`, bottom border `ctp-overlay`) — matches Phase 1 tracker header exactly
   - 5 columns, fixed widths:

| Column | Width | Content |

### Operations log drawer — Phase 3 tab (D-09 — reuse of Phase 2 D-18 pattern)

The Phase 2 operations log drawer gains a 5th tab kind: `Scrape`. No drawer chrome changes. The tab activation rules (auto-open on new spawn, auto-collapse 5 s after clean exit, persist-on-error, 4-tab max with oldest-inactive eviction) are inherited verbatim.

**Scrape tab appearance (inherits all DrawerTab states from Phase 2):**

### Pipeline panel — transparent Phase 3 interaction

The Phase 2 `PipelinePanel` receives no UI changes in Phase 3. The Promote action appends to `data/pipeline.md` via IPC; chokidar detects the change and the existing `FileChangeBanner` appears in the Pipeline panel on next focus (or immediately if the panel is active) — matching Phase 1's file-watch contract. The user sees the promoted company appear in the Pipeline inbox through the existing live-reload path; no new Pipeline panel UI is required.

**Why not also show the promote action in Pipeline?** The Discover → Pipeline data flow is one-directional (Promote writes; Pipeline reads). Duplicating the Promote button in Pipeline panel would invite confusion about where the operation "lives". The Phase 3 promote UX lives inside Discover, end of story.

## Accessibility Contract

Extends Phases 1 and 2. All prior rules apply; Phase 3 additions below.

- **Discover panel focus order:** Drop alert banner (if present) → Add Firm button → Filter toggle (Matched) → Filter toggle (All) → Scraper health handle → (expanded only) health rows → company table header (decorative; sticky skip) → first company row Promote button → subsequent rows in visual order.
- **Company table ARIA:** `role="grid"` on the virtualized list wrapper, `role="row"` on each row, `role="gridcell"` on each cell (matches the Phase 1 tracker pattern). The Promote button inside each row is a proper focusable `<button>`, not a clickable div.
- **Promote button ARIA:** `aria-label="Promote {company name} from {firm}"` — screen readers hear the scope; generic `"Promote"` alone would be ambiguous across a 100-row table.
- **Promoted ✓ badge ARIA:** `aria-label="Promoted to pipeline"` — the badge is non-interactive but must announce the completed state.
- **Scraper health accordion:** `aria-expanded` reflects collapsed/expanded; `aria-controls="scraper-health-body"`; the expanded body has `role="region"` with `aria-label="Scraper health details"`.
- **Filter toggle:** implemented as a `role="group"` containing two `role="button"` elements with `aria-pressed={active}`.
- **Drop alert banner:** `role="status"` with `aria-live="polite"` (warn tier) or `role="alert"` with `aria-live="assertive"` (critical tier, > 40% drop).
- **Add Firm modal focus trap:** On open, focus moves to the Firm name input. Tab cycles within the modal. Escape dismisses. Focus returns to the Add Firm button on close.
- **Add Firm modal ARIA:** `role="dialog"` with `aria-modal="true"` and `aria-labelledby` pointing to the `"Add VC Firm"` title.
- **Add Firm Discard button ARIA:** `aria-label="Discard new firm and close dialog"` — the screen-reader announcement names the specific action, matching the "no generic labels" copy rule.
- **Add Firm field validation:** Invalid fields get `aria-invalid="true"` and `aria-describedby` pointing to the inline error element (announced to screen readers without interrupting).
- **Tooltip copy (Funded / Match hover):** implemented via `title` attribute (native HTML tooltip, platform accessibility inherited — matches the Phase 1 Status dropdown tooltip pattern). No custom hover-only affordance.
- **Color is never the sole differentiator:**
  - Funded badge includes the text `"Funded"`; Match includes `"Match"`. Absence renders a visible `—` em-dash, not just empty space.
  - Promote vs. Promoted ✓ differ in text content, not just color (blue outlined button vs. green filled badge with checkmark).
  - Scraper health statuses include dot color AND a Label word (OK / Stale / Error).
  - Drop alert banner tier differs in color AND copy wording (warn = `"…may have changed layout"` vs. critical = `"…check the scraper adapter"`).
- **Contrast (spot-checked):**
  - `ctp-text` (`#cdd6f4`) on `ctp-base` (`#1e1e2e`) ≈ 12.3:1 (AAA)
  - `ctp-text` on `ctp-surface` (`#313244`) ≈ 11.4:1 (AAA) — carried from Phase 2 spot-check
  - `ctp-base` text on `ctp-green` (`#a6e3a1`) ≈ 9.1:1 (AAA) — badge fills
  - `ctp-base` text on `ctp-blue` (`#89b4fa`) ≈ 7.6:1 (AAA) — Promote in-flight, Add Firm, Save Firm
  - `ctp-blue` text on `ctp-base` ≈ 5.9:1 (AA Large) — Promote idle outline button
  - `ctp-yellow` text on `ctp-yellow/15` over `ctp-base` ≈ 10.2:1 (AAA) — drop alert banner copy
- **Keyboard-only operability:** Every Phase 3 interaction in the table above is reachable via keyboard. No hover-only affordances (tooltips are enhancements, not gating information).
