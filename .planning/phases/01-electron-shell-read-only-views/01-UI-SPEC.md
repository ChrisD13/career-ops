# Phase 1 — UI Design Contract: Electron Shell + Read-Only Views

> Visual and interaction contract for Phase 1 frontend implementation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none — plain Tailwind CSS | Default: shadcn declined; data-dense desktop app does not benefit from CMS-style component overhead |
| Preset | not applicable | — |
| Component library | none — custom Tailwind components | — |
| Icon library | lucide-react | Standard React icon library; tree-shakable; matches Tailwind sizing tokens |
| Font | Inter (system fallback: ui-sans-serif, system-ui, sans-serif) | Default: legible at data-dense sizes; no external font load required — use local Inter via CSS font stack |

**shadcn gate result:** No `components.json` found. This is a data-dense Electron desktop app targeting power users managing 740+ rows. shadcn is optimized for consumer web UIs and introduces component overhead (Radix primitives, class-variance-authority) that provides no benefit for a tight electron-vite build with no end-user distribution. Decision: Tool: none. Manual Tailwind components throughout.

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, inline padding within badges |
| sm | 8px | Table cell horizontal padding, compact element spacing |
| md | 16px | Sidebar item padding, section inner padding |
| lg | 24px | Panel padding, card spacing |
| xl | 32px | Layout column gap |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level outer margin (unused in Phase 1 — full-bleed layout) |

Exceptions:
- Table row height: 32px (fixed, set on react-window row renderer — not a spacing token)
- Nav sidebar width: 200px expanded / 48px collapsed — not on 4px grid by design
- Sidebar nav item height: 40px (touch-friendly, within react-window row parity)
- File-change banner: 40px height — fixed strip at top of content area

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 13px | 400 (regular) | 1.5 | Table cell values, report body text, pipeline URLs |
| Label | 11px | 600 (semibold) | 1.4 | Table column headers, nav item labels, badge text, metadata |
| Heading | 16px | 600 (semibold) | 1.3 | Panel titles (e.g. "Reports"), report H2 headings, section headers |

**Weights used:** 400 and 600 only. No intermediate weights.

**Font stack:** `'Inter', ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, sans-serif`

**Report markdown rendering (react-markdown):** Map markdown heading levels to Typography tokens:
- `# H1` → Display (20px / 600)
- `## H2` → Heading (16px / 600)
- `### H3` → Label (11px / 600, uppercase letter-spacing 0.05em)
- Body paragraphs → Body (13px / 400)
- Code blocks → `font-mono` 13px / 400, background `#313244`, border `#45475a`
- Tables → Body (13px / 400), header row Label (11px / 600)

## Layout Contract

Source: CONTEXT.md decisions D-06, D-07; Claude's Discretion (navigation structure, split pane sizing).

**Primary visual anchor:** the Score badge column — the colored pill system draws the eye first and signals match quality at a glance.

### Navigation structure

**Left sidebar** — vertical nav rail. Not a tab bar.

Rationale: Phase 2 adds CV viewer, API settings, batch controls. A sidebar scales to 6–8 items without crowding. Tab bar breaks at 5+ items.

| Sidebar state | Width | Content |
|---------------|-------|---------|
| Expanded | 200px | Icon + label per nav item |
| Collapsed | 48px | Icon only, tooltip on hover |

Default state: expanded.

Nav items (Phase 1):
1. **Tracker** (table icon) — `data/applications.md` virtualized table
2. **Reports** (file-text icon) — `reports/*.md` browse list (D-07)
3. **Pipeline** (inbox icon) — `data/pipeline.md` pending URLs

Active item: Blue accent (`#89b4fa`) left border (3px) + text color change to blue. Inactive: `subtext` color.

### Tracker panel (ELEC-02, D-01 through D-04)

- Full-width virtualized table via react-window — `FixedSizeList` with `height=32px` per row
- 9 columns in order: `#` | `Date` | `Company` | `Role` | `Score` | `Status` | `PDF` | `Report` | `Notes`
- Fixed table header (sticky, not scrolled) at 36px height, Label typography, `#313244` background
- Column widths (fixed, no resize in Phase 1):

| Column | Width | Notes |
|--------|-------|-------|
| # | 48px | Right-aligned, monospace |
| Date | 88px | YYYY-MM-DD |
| Company | 160px | Left-aligned, truncate with ellipsis |
| Role | 200px | Left-aligned, truncate |
| Score | 72px | Centered, colored badge |
| Status | 120px | Status pill badge |
| PDF | 48px | Centered, icon only |
| Report | 72px | Centered, clickable link |
| Notes | flex (remaining) | Left-aligned, truncate |

- Row hover: background `#45475a` (overlay)
- No row selection state in Phase 1
- Alternating row tint: none — hover is sufficient for power users

**Score badge:** Pill shape, 4px border-radius, 4px horizontal padding.
- ≥ 4.0: Green background `#a6e3a1`, text `#1e1e2e`
- 2.5–3.9: Yellow background `#f9e2af`, text `#1e1e2e`
- < 2.5: Red background `#f38ba8`, text `#1e1e2e`
- Missing/unparseable: `overlay` background `#45475a`, text `subtext`

**Status badge:** Pill shape, 4px border-radius, 4px horizontal padding.
- Evaluated: Mauve `#cba6f7` / text `#1e1e2e`
- Applied: Sky `#89dceb` / text `#1e1e2e`
- Responded: Sky `#89dceb` / text `#1e1e2e`
- Interview: Peach `#fab387` / text `#1e1e2e`
- Offer: Peach `#fab387` / text `#1e1e2e`
- Rejected: overlay `#45475a` / text `subtext`
- Discarded: overlay `#45475a` / text `subtext`
- SKIP: overlay `#45475a` / text `subtext`

**PDF column:** Checkmark icon (lucide `Check`, green) if PDF exists; dash `—` in subtext if absent.

**Report column (D-06):** Clickable link text "Open report" in blue (`#89b4fa`), underline on hover. Click opens the split-pane layout.

### Status dropdown (D-09)

**Decision:** Render as a native `<select>` element that is **visually styled but functionally disabled** in Phase 1.

- Element is `disabled` attribute — not clickable
- Tooltip on hover: `title="Status editing available in Phase 2"`
- Visual: grayed border `#45475a`, cursor `not-allowed`
- Options populated from `templates/states.yml` at startup — demonstrates the data plumbing works before Phase 2 enables persistence
- Rationale: Silent non-persistence would confuse users who change status and see it disappear on refresh. Disabled + tooltip is honest. Omitting it entirely loses the Phase 1 proof point for ELEC-03.

### Split pane layout (D-06)

Triggered when user clicks an "Open report" link from the Tracker panel.

| Pane | Width | Content |
|------|-------|---------|
| Left (Tracker) | 45% | Tracker table, unchanged, continues to show all rows |
| Right (Report) | 55% | Report rendered as formatted markdown |

- Both panes scroll independently (separate overflow containers)
- Report pane header: report filename + "×" close button (Blue icon, returns to full-width tracker)
- No resize handle in Phase 1 — fixed 45/55 split
- Split activates within the main content area (sidebar remains visible)

### Reports panel (D-07)

Standalone nav item — not the split pane.

- Left column: file list of all `reports/*.md`, sorted by filename (descending — newest first by report number)
- Each list item: report number + company name extracted from filename, date extracted from filename
- Selected item highlighted with blue left border (`#89b4fa`, 3px)
- Right side: report rendered as formatted markdown (react-markdown)
- Default state (no report selected): empty state (see Copywriting Contract)

### Pipeline panel (ELEC-05)

- Simple list of URLs from `data/pipeline.md`
- Each item: full URL as monospace body text, date added if parseable from the file
- No remove/delete action in Phase 1 (read-only)
- Empty state (see Copywriting Contract)

### File-change banner (D-04, D-05)

Triggered by chokidar v5 when any watched file changes while app is open.

- Fixed strip: 40px height, positioned at top of main content area (below app title bar, above panel content)
- Background: Yellow tint `#f9e2af` at 15% opacity over `#313244` base — `rgba(249, 226, 175, 0.15)`
- Icon: lucide `RefreshCw` (14px, yellow `#f9e2af`)
- Text: "Files changed — click to refresh" (Body, 13px, yellow `#f9e2af`)
- Entire banner is clickable (cursor pointer) — triggers reload of all in-memory data from disk
- Dismisses automatically after reload
- Multiple file changes while banner is visible: banner stays, does not flash repeatedly

## Interaction Contract

| Interaction | Trigger | Result |
|-------------|---------|--------|
| Open report from tracker | Click "Open report" link in Report column | Split pane opens: tracker left (45%), report right (55%) |

| Status dropdown (Phase 1) | Click | No-op — disabled element |
| Collapse sidebar | Click collapse toggle | Sidebar narrows to 48px, labels hidden, icons remain |
| Expand sidebar | Click expand toggle | Sidebar expands to 200px, labels visible |

## Accessibility Contract

- All interactive elements have `:focus-visible` ring: 2px solid `#89b4fa` (blue), 2px offset
- Lucide icons used decoratively have `aria-hidden="true"`
- Clickable icon buttons have `aria-label` describing the action
- File-change banner is `role="status"` (announces to screen readers without interrupting)
- Disabled status dropdown has `title` attribute for tooltip (native HTML, no JS required)
- Table: `<table role="grid">` semantics even if implemented as virtualized divs — apply `role="row"`, `role="gridcell"` to react-window row components
- Color is never the sole differentiator — score badges include numeric text; status badges include text label
