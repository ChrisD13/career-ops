<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer→main | Renderer (future Chromium sandbox) will call IPC channels; narrow contextBridge surface defined in Plan 02 |
| filesystem→app | App reads user-owned markdown/YAML files; path traversal risk on report paths (mitigated in Plan 02) |
| build-time→runtime | Malicious dependency could execute at install; pinning specific versions reduces supply-chain blast radius |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | electron/package.json dependency pins | mitigate | Pin exact versions for electron (41.2.2), react (18.3.1), typescript (5.8.3), react-window (1.8.10), zod (3.24.3), react-markdown (10.1.0), remark-gfm (4.0.1), rehype-sanitize (6.0.0) — minimizes drift and supply-chain surprise. |
| T-01-02 | Elevation of Privilege | npm workspace hoisting | mitigate | Do NOT add `workspaces` to parent package.json; isolate electron/ node_modules. Verified by absence of `/home/desachri/JobEngine/node_modules/electron` post-install. |
| T-01-03 | Spoofing | Content-Security-Policy in renderer HTML | mitigate | CSP meta tag with `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'` set in index.html (defense in depth; main process sets header in Plan 02). No `unsafe-eval`, no remote origins except Vite HMR in dev. |
| T-01-04 | Information Disclosure | Build output committed to git | accept | `electron/out/` and `electron/dist/` in `.gitignore`; `node_modules/` also ignored. Low risk — build outputs do not contain secrets. |
</threat_model>
