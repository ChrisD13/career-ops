## UpdateBanner Component Contract

### Mount Point

Mount `<UpdateBanner />` inside `<main>` in `App.tsx`, immediately above `<FileChangeBanner />`.

```tsx
<main className="flex-1 flex flex-col min-w-0">
  <UpdateBanner />                              {/* new — phase 5 */}
  <FileChangeBanner visible={filesChanged} onRefresh={handleRefresh} />
  <div className="flex-1 min-h-0 overflow-hidden">
    {renderPanel()}
  </div>
</main>
```

### Updater States — What Renders vs. What Is Silent

| Phase | Event Source | User-Facing | Render |
|-------|-------------|-------------|--------|
| `idle` | Pre-check (initial render) | No | `null` |
| `checking` | 5s delay started, check initiated | No | `null` |
| `downloading` | `update-available` received | No | `null` — do not show download progress |
| `downloaded` | `update-downloaded` received + version not dismissed | **Yes** | Full banner |
| `error` | `error` event | No | `null` — fail silently, log to console only |
| `not-available` | `update-not-available` event | No | `null` |

**Rule:** the banner renders **only** when `phase === 'downloaded'`. All other states are invisible to the user. The executor must not add UI for downloading, checking, or error states.

### Banner Structure (downloaded state only)

```
┌────────────────────────────────────────────────────────────────────────────────┐
│ [Download icon]  Update available: v{version}           [Install Now]  [Later] │
│                  {release notes line 1}                                        │
│                  {release notes line 2}  (if present)                          │
│                  {release notes line 3}  (if present)                          │
└────────────────────────────────────────────────────────────────────────────────┘
padding: py-2 px-4 (8px top/bottom, 16px left/right)
```

**Release notes rendering:** Render up to 3 lines of release notes below the version heading. The main process (`updater.ts`) already slices `info.releaseNotes.split('\n').slice(0, 3)` before sending via IPC. The renderer receives a pre-truncated string and renders it with `whitespace-pre-line` so newlines display as line breaks. If `releaseNotes` is `null` or empty string, render the version line alone (no notes section).

Layout is a two-column flex row (`justify-between items-start`) with:
- Left column: `Download` icon + version/notes text block
- Right column: action buttons stacked or side-by-side (`flex gap-2`)

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Install Now` |
| Dismiss CTA | `Later` |
| Version line (with notes) | `Update available: v{version}` |
| Version line (no notes) | `Update available: v{version}` |
| Release notes | First 3 lines of release notes text, verbatim from GitHub Release body, rendered below version line |
| Empty state | Not applicable — component returns `null` when no update |
| Error state | Not applicable — errors are silent (log to console only per CONTEXT.md) |

### "Later" Semantics — Important

"Later" means: dismiss this version permanently — do not show this banner again for `v{version}`. It does NOT mean "remind me again this session". The button label is intentionally understated to avoid alarming users, but the implementation persists the dismissed version to `dismissed-update.json` in Electron's `userData` directory. If a newer version becomes available on the next launch, the banner returns automatically.

No confirmation dialog is required for "Later" — it is a non-destructive dismiss of a notification.

No confirmation dialog is required for "Install Now" — the user has clicked a clear, labeled CTA. The app will quit and relaunch as expected desktop update behavior.
